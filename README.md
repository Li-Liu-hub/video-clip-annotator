# 视频片段标注平台

管理员把机器人示教视频分配给标注员，标注员在视频上标出有效时间段，管理员按「提交日期」
统计每人每天的有效工作量。

替掉的是一套手工流程：标注员把起止时间填进表格，管理员每天手工汇总，**数字经常对不上**。

---

## 快速开始

```bash
npm install && npm run dev
```

打开 <http://localhost:3000>，用下面任一账号登录。

**环境要求**：Node.js ≥ 20.9。
不需要装数据库，不需要编译器，不需要联网。

首次启动会自动建库并灌入演示数据（`predev` 钩子触发）。

## 演示路径

按这个顺序走，能看到完整的闭环：

1. **alice 登录** → 任务列表里有一条 `pending` 的「单臂抓取 · 侧向接近」
2. 点「领取」→ 进入标注工作台
3. 在时间轴上拖出 2–3 个时间段（或按 `I` / `O` 打点）
4. 点「提交」
5. **换 admin 登录** → 统计页看到今天多了一笔，按人视图里是 alice
6. 把这个任务**退回** → 统计页出现一笔负数冲正
7. **审计页**可以看到从创建到退回的每一步

第 6 步是这个项目最值得看的地方：退回之后，**前一天的汇总数字完全不变**。

---

## 它解决什么问题

「数字对不上」的根因不是人不细心，而是**同一份数据被反复重算**。

所以这里的统计不是「扫一遍当前状态求和」，而是**记账**：

```
提交 → 冻结快照 + 写一笔 +2:00（记在提交日）
退回 → 写一笔 −2:00（记在退回日）
重提 → 写一笔 +1:35（记在重提日）
```

每天的汇总 = `SUM(账本) GROUP BY 日期`。**历史日期一旦写入，任何后续操作都改不了它。**

代价是某天可能出现负数——这是可解释的净差，比「昨天的数字凭空消失」好得多。

## 技术栈

| 层 | 选择 |
|---|---|
| 框架 | Next.js 15（App Router） |
| 语言 | TypeScript（strict） |
| 数据库 | SQLite + better-sqlite3 |
| 数据访问 | 手写 SQL + repository 层 |
| 样式 | Tailwind CSS v4 |
| 认证 | 自建 session + httpOnly cookie |
| 测试 | Vitest |

选型理由见 [`docs/DESIGN.md`](docs/DESIGN.md) 的 ADR 记录。

**为什么是 SQLite**：单机部署，几十名标注员、每天几百次写事务，负载余量约三个数量级。
更重要的是零外部依赖——评分人 `npm install && npm run dev` 就能跑，不用装数据库。

## 几个设计要点

**租户的粒度是标注员个人。** 一个标注员一个租户，1:1，由数据库的部分唯一索引保证。
管理员不属于任何租户，因此可以跨租户分配任务。

**视频不进 `public/`。** 静态目录意味着知道 URL 就能下载，租户隔离形同虚设。
视频存 `data/videos/`，通过带鉴权的路由提供，自行实现 HTTP Range 以支持拖动播放。

**不重叠有两道防线。** 应用层校验为了给可读提示，数据库触发器为了兜底——
两个请求同时通过检查、或将来某个新接口忘了校验，都会被数据层拦住。

**审计与账本分开。** 账本算工钱（只记影响时长的事件），审计追责任（登录、上传、越权尝试全记）。
混在一起，统计会被污染，或者出问题查不到人。
