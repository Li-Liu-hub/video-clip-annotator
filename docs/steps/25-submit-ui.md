# F3 · 提交与重新打开的界面入口

**做什么**：让标注员能真的点「提交」，让被退回的任务能点「重新打开」。

**依赖**：F1、F2

**预计**：0.5 小时

---

## 为什么必须有这一步

F1 写了 `submitTask` 与 `POST /api/tasks/:id/submit`，F2 写了 `reopenTask`，
但**两个接口在界面上都没有入口**：

- 工作台底部没有「提交」按钮 → 标注员标完只能干瞪眼
- 任务列表的「已退回」行没有「重新打开」→ `reopenTask` 永远不被调用

接口正确但没人能调用，等于没做。M2「能标片段」到现在还差这一下。

---

## 提交前的确认

提交是不可逆的（F1 把它做成了事务），点错没有反悔办法。所以提交前要确认一次：

```
┌─────────────────────────────────────┐
│ 提交任务                             │
│                                     │
│ 共 3 个片段，合计 12.4 秒             │
│ 提交后不能再修改，需要调整只能请管理员退回。 │
│                                     │
│              [取消]  [确认提交]       │
└─────────────────────────────────────┘
```

- **必须显示片段数与总时长**：这两个数字就是提交后计入账本的内容，
  用户有权在看一眼之后再决定
- 空片段时按钮就该禁用，而不是点了才报「还没有标注任何片段」
- 提交中按钮变「提交中…」并禁用，防连点

---

## 任务列表的「重新打开」

`rejected` 行原本只有「已退回」和一个原因。加一个「重新打开」：
调 `POST /api/tasks/:id/reopen`，成功后把该行状态改成「进行中」，原因保留。

**不要**重新拉整页：列表页在 D 组就是这么做的（`reject` 成功后原地改行），
保持一致。

## 契约（不可改动）

```ts
// SubmitBar.tsx
type Props = {
  segmentCount: number;
  totalMs: number;
  /** 提交中：禁用并改文案 */
  busy: boolean;
  onSubmit: () => void;
  /** 提交失败的提示。null 表示无错误 */
  error: string | null;
};
```

提交成功后由 `Workbench` 通知外层——**用 `router.refresh()` 而不是本地改状态**：
提交会改变任务的 `status`，进而改变整页的只读/可写形态（E8a 的 `readOnly`）。
本地改状态只改了组件，页面还是「可编辑」的样子。

---

## 实现要点

### 1. 按钮禁用条件

```tsx
disabled = segmentCount === 0 || busy
```

`segmentCount === 0` 时按钮禁用且文案是「还没有片段」——**不要**让用户点了才看到错误。

### 2. 确认用原生 `<dialog>` 还是内联展开

用内联展开（点「提交」后在按钮区展开一行确认），不弹模态框：

- 项目里没有模态框先例，为一个确认引入一套焦点管理不值
- 内联展开的焦点是自然的，不需要 `focus trap`
- 用户能看到背后的片段列表，确认「就是这些」

### 3. 提交成功后整页刷新

```tsx
await fetch(...);
router.refresh();   // 不是 setState
```

理由见契约。`refresh()` 会重跑 server component，`getWorkTask` 返回 `submitted`，
页面自动切成 E8a 的只读形态。

### 4. 失败提示复用已有的 `saveError`

工作台已经有一个 `aria-live` 的错误区（E4 建立的）。提交失败往里写，
不要新起一个 toast。

### 5. `totalMs` 与提交后账本的口径一致

`segments.reduce((s, x) => s + (x.endMs - x.startMs), 0)` ——
与 F1 的 `totalMs` 同一个算法。**不要用视频时长**，那是 E1 就定下的规矩。

## 验收

**自动**

- [ ] `sumDuration` 或等价纯函数：空数组 → 0；单段 → 长度；多段 → 累加
- [ ] 现有 547 例全绿

> 其余是交互，项目无组件测试设施（INDEX O1c），只能手工。

**手工**

- [ ] 标 3 段 → 底部显示「共 3 个片段，合计 X 秒」
- [ ] 点「提交」→ 展开确认 → 确认后按钮变「提交中…」
- [ ] 提交成功 → 页面变成只读（徽章「已提交」、无删除按钮、时间轴拖不动）
- [ ] 没有片段时 → 按钮禁用，文案提示还没标
- [ ] 任务列表里已退回的行 → 有「重新打开」→ 点了变「进行中」且原因还在
- [ ] 重新打开后再进工作台 → 顶部显示退回原因

## 易错点

| 陷阱 | 后果 |
|---|---|
| 提交后本地改状态不 refresh | 页面仍是可编辑形态，用户能继续拖，一拖就 409 |
| 不显示片段数与时长 | 用户不知道提交的是什么，账本数字没有预期 |
| 空片段时按钮可点 | 点了才报错，多一次无谓往返 |
| 用视频时长算总时长 | 账本虚高，G3 的看板全是假数字 |
| 重新打开后整页刷新 | 与 D 组的 reject 行为不一致，且丢失滚动位置 |
