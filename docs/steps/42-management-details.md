# R2 · 管理明细与提交审核

用户需要从管理页面判断：谁在哪一天完成了哪项任务、提交了多少片段；审核时能看到实际片段；发布时能查看各空间已有任务。

本需求取代 G1/G3 中“按人仅一行汇总”的原始契约。

后续调整：个人工作量只保留按日和按任务；旧的按人页面链接回落按日。管理员审核和标注工作台共用视频舞台、自绘播放按钮、时间显示、片段侧栏和片段列表，审核时间轴使用现有只读组件。冻结快照、历史版本及片段终点暂停规则保留。

## 最终行为

- 按人统计以 `annotator_id + entry_date + task_id` 分组，显示姓名、提交日期、任务、有效片段数、净时长、提交次数、退回次数。人员仍按所选区间总净时长排序，人员内部按日期倒序。
- 时长以账本 `SUM(delta_ms)` 为准；有效片段数按账本关联快照的 `segment_count` 随提交增加、随退回扣除。账本条目数保留在接口与导出中，避免把交易条数误称为视频片段数。
- CSV 与页面使用同一查询，导出包含日期、任务 ID、标题、片段数和提交/退回次数。
- 管理员任务列表提供审核入口，进入 `/admin/tasks/:id/review`。列表页码与状态筛选随返回链接保留。
- 审核页读取 `submissions.segments_json`，显示冻结标签及时间范围。点击片段定位到起点并播放，到终点自动暂停；可拖动播放器看前后画面。页面初次打开不自动播放。
- 支持切换历史提交；只有最近一次提交且任务仍是 submitted 时可退回。退回携带提交 ID，并在事务内核对当前快照，防止退回未看过的新版本。
- 旧快照的时间若超出视频长度，仍显示原记录并提示异常；可播放部分止于视频末尾，起点超出素材的片段禁用播放。保留原始数据供审核核对。
- 发布页各空间提供“查看现有任务”，独立展开标题、状态、领取人及视频，每页 20 条。同视频有提示；展开、翻页均保留表单内容，查看提交在新标签页打开。
- 空间明细接口与审核查询均校验管理员角色；标注员的统计查询继续使用租户与本人双重过滤。

## 验证入口

- `tests/stats.test.ts`：跨日期/跨任务拆分、快照片段数、冲正归零、租户与本人范围。
- `tests/csv.test.ts`：按人 CSV 各列与公式防护。
- `tests/review.test.ts`：冻结快照、角色权限、异常数据、过期提交退回回滚。
- `tests/review-player.dom.test.tsx`：起点播放、终点暂停、历史只读、越界片段提示、退回绑定版本。
- `tests/task-query.test.ts`、`tests/task-form.dom.test.tsx`：空间隔离、分页、表单保留。
- `scripts/browser/browser-management.py`：真实素材播放边界、页面入口、CSV 下载、发布展开与退回后统计归零。

浏览器门禁使用独立数据库及视频目录，Python 输出强制 UTF-8，防止污染运行素材或因 Windows 编码中断。
